**3\. Core Functionality: The Tool Foundry**

S.T.R.A.T.A. replaces legacy static toolsets with a dynamic, just-in-time (JIT) manufacturing workflow.

### **3.1 Autonomous Tool Manifestation**

When a capability gap is identified by the Aether framework, S.T.R.A.T.A. triggers the **ToolGen** pipeline. This process utilizes a coding-efficient LLM (e.g., qwen2.5-coder) to:

1. **Synthesize**: Generate Go-based source code based on precise requirements.  
2. **Verify**: Perform static analysis and compilation checks in a sandboxed environment.  
3. **Persist**: Store the tool as a first-class plugin on the sovereign VPS.

### **3.2 The Async Lifecycle**

To prevent network timeouts during complex generation tasks, S.T.R.A.T.A. utilizes an asynchronous job model. Agents post a requirement to /admin/plugins, poll for completion, and then activate the tool via the /admin/plugins/{name}/enable endpoint.

## ---

**4\. Security and Sovereignty**

S.T.R.A.T.A. is engineered for high-security environments where cloud dependencies are prohibited.

### **4.1 The Preflight Gate**

Before any new skill or tool is manifested, S.T.R.A.T.A. enforces a **Preflight Check** (POST /skills/preflight). This gate audits the intent and requested domains against local security policies, returning a decision of allow, deny, or review.

### **4.2 Trusted Auto-Enablement**

The engine features a sophisticated trust model. Tools generated by **Trusted Publishers** (configured via GLM\_TRUSTED\_PLUGIN\_PUBLISHERS) or those carrying **Trusted Prefixes** are auto-enabled, while all others remain pending until manual admin authorization.

### **4.3 HMAC-Signed Heartbeats**

Identity continuity across the mesh is maintained via HMAC-SHA256 signed heartbeats, ensuring that the "Pulse" of the substrate remains uncompromised by replay attacks.
